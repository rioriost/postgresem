The frozen stable manifest release label advances to 1.0.1 to match the executable. The v1.0.0-only external-evidence exception does not authorize publishing this new stable tag.

## Reproducible macOS build

Use one consistent Rust toolchain with both `aarch64-apple-darwin` and `x86_64-apple-darwin` standard libraries installed. Set `DEVELOPER_DIR` to Xcode 27 RC. Build each target with `CARGO_PROFILE_RELEASE_BUILD_OVERRIDE_DEBUG=true` and `CARGO_PROFILE_RELEASE_STRIP=none`; this keeps build-time procedural macro dylibs loadable on macOS 27. The failure without these overrides was `mis-aligned LINKEDIT string pool`, tracked in https://github.com/rust-lang/rust/issues/157750.

Use `MACOSX_DEPLOYMENT_TARGET=11.0` for arm64 and `10.12` for x86_64, then `cargo build --locked --release --package postgresem --target <target>`. The current local build uses the Rustup stable toolchain consistently; do not mix Homebrew rustc with Rustup target libraries. SDK selection and compiler versions must be recorded with the release artifacts.
